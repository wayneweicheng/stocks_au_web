# Checkpoint 05 — frozen 40 packet audit and runtime-aligned REVIEW archive

## Critical finding: existing baseline is NOT correct

The existing 20261018-a 40-packet archive is immutable. Its old 869 historical trade rows were compared to independently audited subject-symbol price labels: 862 have a corrected D0 counterpart; **only 1/869** old entry prices matched and **0/869** directional returns matched (7 have no corrected eligible D0). `baseline_40_legacy_ledger_audit.csv/json` records every discrepancy. The archive's original source hash matches the original research inputs; this is not a file-corruption or hash problem. It is a previously identified historical entry-time/session labeling problem. The old 2.11 OOS replay PF was also based on NQMAIN, not subject stock prices. Neither number represents a valid current baseline.

A first rebuild using corrected stock labels, but still using research-calculated features, produced 1,298 trade rows. **Runtime-parity audit revealed 458 mismatches and one incomplete source day** among its 1,298 ledger rows (839 matched). Historical ranks/shocks differ where source filters, 60-history readiness or rank windows differ; these are not safe to call identical to production triggers. That archive is marked **BLOCKED** and kept only as a zipped diagnostic; it is not the recommended comparator.

## Unexpected live state: operator attention required

A **read-only** SQL deployment audit (`baseline_40_live_state_read_only.csv/json`) found all 40 frozen codes already have enabled `LIVE_MANUAL` deployments on the old `1.0.0-production` version, with notifications enabled and **80 enabled schedules** (EVALUATE and MONITOR). ExecutionEnabled=0 for all 40. The old source hashes in SQL match the original archived descriptors. SUBJECT roles are stored as bare tickers; the runtime normalizes them to `.US`. This **contradicts the earlier statement that the 40 were not activated**. There are 111 deployment rows across these 40 codes including disabled/historical/backtest rows; only the 40 enabled live-manual rows are counted as active. The new review ZIP has **not** been provisioned and no SQL row or schedule was changed. Do not assume `HARD_DISABLED` prevents erroneous notifications.

**Action requiring explicit user decision:** consider pausing the existing 40 live-manual notification schedules/deployments pending independent review, but do not change them silently. This research task did **not** authorize live modification or external notification changes; the audit preserves exact keys in the CSV for an operator-approved rollback.
